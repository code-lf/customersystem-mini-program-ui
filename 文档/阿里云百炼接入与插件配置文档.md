## 一、结论与当前状态

当前项目已经有 AI 助手页面，但还没有真正接入阿里云百炼：

- `pages.json` 已把“AI助手”放入底部 tabBar。
- `pages/ai/index.vue` 是入口页，展示能力卡片和推荐问题。
- `pages/ai/chat.vue` 仍使用 `setTimeout`、固定文案和 `uiProducts` 模拟回答。
- `api/ai.js` 已声明 `POST /ai/ask`，但聊天页没有调用它。
- 商品搜索、商品详情、商品分类三个后端接口已实测可访问。
- `POST /crm/quote` 的请求结构已经通过完整 OpenAPI 文档确认；为避免生成垃圾报价单，本次只核对结构，没有执行 POST 写入测试。

当前 MCP 服务配置四个工具：

1. `search_products`：搜索商品。
2. `get_product_detail`：查询商品详情与技术参数。
3. `get_product_categories`：查询分类树。
4. `create_quote_solution`：仅在用户明确确认后创建报价单。

## 二、tabBar 与 AI 调用链分析

### 2.1 当前 tabBar

| 顺序 | 页面 | 名称 | 作用 |
| --- | --- | --- | --- |
| 1 | `pages/index/index` | 首页 | 首页与业务概览 |
| 2 | `pages/product/index` | 产品 | 商品搜索、分类和详情 |
| 3 | `pages/solution/index` | 报价单 | 商品配置、价格核算与报价方案 |
| 4 | `pages/ai/index` | AI助手 | AI 快捷提问与对话入口 |
| 5 | `pages/my/my` | 我的 | 用户与账户功能 |

AI 图标为 `static/tabbar/ai.png` 和 `static/tabbar/ai_active.png`。它位于产品和报价单之后，适合作为独立一级入口保留：AI 可以先查商品，确认后再引导用户进入报价流程。

### 2.2 当前与目标调用链

```text
当前：AI tab -> ai/index.vue -> ai/chat.vue -> 本地 setTimeout -> 固定 Mock 回答

目标：AI tab -> ai/chat.vue -> 自有后端 POST /api/ai/ask
     -> 后端携带百炼 API Key 调用百炼应用
     -> 百炼智能体按需调用商品插件
     -> 后端返回文本、会话 ID 和结构化商品卡片
```

百炼 API Key 必须放在自有后端，不能写入 uni-app、小程序包、H5 代码或 `VITE_*` 环境变量。

## 三、接口基址、请求头与响应约定

### 3.1 当前开发基址

`config/app.js` 当前配置：

```text
https://3e0eee0e.r25.cpolar.top/api
```

这是临时穿透域名，只适合开发联调。正式插件必须使用稳定、受控、支持 HTTPS 的生产域名。

### 3.2 当前前端请求头

```http
Content-Type: application/json
channel: 1
token: <登录后的业务 token>
```

完整 OpenAPI 把四个接口都声明为 `apiToken` 鉴权，Header 名称为 `token`。开发环境中的三个只读商品接口已经实测为“不带 token 也能返回数据”，这说明当前真实权限行为与接口文档存在差异；上线前应由后端统一权限策略。

当前百炼 MCP 服务公共 Header 为：

```http
channel: 1
```

创建报价单工具额外把 `token` 配置成“Header / 必填 / 业务透传”，不能让模型生成或改写该值。生产环境更推荐由自有后端使用稳定的服务级鉴权，例如：

```http
Authorization: Bearer <PLUGIN_TOKEN>
```

这个插件 Token 与百炼 API Key 是两种不同凭证，不能混用。普通用户 token 会过期，也不应固定写在百炼插件配置里。

### 3.3 统一响应

```json
{
  "code": 1,
  "msg": "SUCCESS",
  "data": {}
}
```

项目封装兼容成功码 `0`、`1`、`200`；本次实测商品接口返回 `code: 1`。

## 四、百炼插件总体配置

在百炼控制台创建“自定义插件”，建议填写：

| 字段 | 建议值 |
| --- | --- |
| 插件名称 | `格宏商品查询助手` |
| 插件描述 | `为格宏 AI 助手提供商品搜索、商品详情与技术参数、分类树查询，并在用户确认后创建报价单草稿。` |
| 插件 URL | `https://<正式业务域名>/api` |
| 是否鉴权 | 生产环境建议开启 |
| 鉴权位置 | Header |
| 鉴权类型 | bearer，或按后端实际规则选择 basic |
| 当前公共 Header | `channel: 1` |
| 业务鉴权 Header | OpenAPI 定义为 `token`；写接口必须由调用方透传，不能写死用户 Token |

工具路径必须以 `/` 开头，并与插件 URL 拼接：

```text
插件 URL：https://api.example.com/api
工具路径：/crm/quote/product/goods
最终地址：https://api.example.com/api/crm/quote/product/goods
```

工具需要在百炼控制台完成在线测试并发布，发布后才能被智能体调用。

## 五、工具 1：商品搜索 `search_products`

### 5.1 基本配置

| 字段 | 填写内容 |
| --- | --- |
| 工具名称 | `search_products` |
| 中文名称 | 商品搜索与选型 |
| 工具描述 | `按商品名称、SKU、型号、条码或其他关键字搜索商品，返回分页商品列表及 goods_id、名称、型号、分类和价格。` |
| 请求方法 | GET |
| 工具路径 | `/crm/quote/product/goods` |
| 提交方式 | `application/json` |

### 5.2 已实测可用的 Query 参数

| 参数 | 类型 | 必填 | 默认 | 取值来源 | 描述 |
| --- | --- | --- | --- | --- | --- |
| `keyword` | string | 否 | 空 | 大模型识别 | 商品名称、SKU、型号、条码或其他关键字。 |
| `category_id` | integer | 否 | `0` | 大模型识别 | 分类 ID；传父分类时同时查询其子分类商品。 |
| `page` | integer | 否 | `1` | 大模型识别 | 页码，从 1 开始。 |
| `limit` | integer | 否 | `15` | 大模型识别 | 每页条数。 |

旧文档中的 `pishu`、`mianji`、`product_type`、`nengxiao`、`lengnuan` 本次实测传入后结果总数不变，说明开发后端暂未执行这些筛选。后端实现并验收前，不要把它们配置成百炼工具入参。

前端页面中的匹数、能效、面积、电源和品牌筛选，有一部分是在拿到列表后由 `pages/product/list.vue` 本地过滤，也不等于后端支持同名参数。

### 5.3 真实响应结构

```json
{
  "code": 1,
  "msg": "SUCCESS",
  "data": {
    "total": 2,
    "per_page": 2,
    "current_page": 1,
    "last_page": 1,
    "data": [
      {
        "goods_id": 438,
        "goods_name": "格力商用GMV-NDR90PMS/A",
        "sku": "0428",
        "unit": "套",
        "spec": null,
        "category_id": 40,
        "category_name": "格力大多联",
        "price": 0,
        "model": "GMV-NDR90PMS/A",
        "comment": ""
      }
    ]
  }
}
```

注意：外层 `data` 是统一响应数据，内层 `data.data[]` 才是商品数组。原文档中的 `data.list[]`、`id`、`goodsname`、`type` 与当前真实接口不一致。

### 5.4 建议输出参数

| 参数路径 | 类型 | 描述 |
| --- | --- | --- |
| `code` | integer | `1` 表示请求成功。 |
| `msg` | string | 业务提示。 |
| `data.total` | integer | 符合条件的商品总数。 |
| `data.per_page` | integer | 每页条数。 |
| `data.current_page` | integer | 当前页。 |
| `data.last_page` | integer | 最后一页。 |
| `data.data` | array<object> | 商品数组。 |
| `data.data[].goods_id` | integer | 商品唯一 ID，详情接口使用。 |
| `data.data[].goods_name` | string | 商品名称。 |
| `data.data[].model` | string | 商品型号。 |
| `data.data[].sku` | string | SKU。 |
| `data.data[].category_id` | integer | 分类 ID。 |
| `data.data[].category_name` | string | 分类名。 |
| `data.data[].price` | number | 价格；0 表示待维护或待确认，不是免费。 |
| `data.data[].unit` | string | 销售单位。 |
| `data.data[].spec` | string | 简要规格，可能为空。 |
| `data.data[].comment` | string | 备注，可能为空。 |

## 八、工具 4：创建报价单 `create_quote_solution`

### 8.1 基本配置

| 字段 | 填写内容 |
| --- | --- |
| 工具名称 | `create_quote_solution` |
| 工具描述 | `仅在用户明确确认报价商品、数量和折扣后创建报价单草稿；未确认时禁止调用。` |
| 请求方法 | POST |
| 工具路径 | `/crm/quote` |
| 请求内容类型 | `application/json` |
| 鉴权参数 | Header `token`，String，必填，业务透传 |

`token` 是当前登录用户的业务凭证，只能由调用方提供。提示词和工具描述必须明确禁止模型生成、猜测或修改 Token。

### 8.2 请求体字段

OpenAPI 的 `QuoteCreateInput` 只有 `items` 是顶层必填字段。当前 MCP 已按下表配置：

| 参数 | 类型 | 必填 | 默认值 | 描述 |
| --- | --- | --- | --- | --- |
| `global_discount_rate` | number | 否 | `100` | 全单折扣率；100 表示不打折。 |
| `category_discounts` | array<object> | 否 | 空 | 分类折扣列表。 |
| `category_discounts[].category_id` | integer | 否 | 无 | 商品分类 ID。 |
| `category_discounts[].discount_rate` | number | 否 | 无 | 该分类的折扣率。 |
| `extra_amount` | number | 否 | `0` | 附加金额，可为正数或负数。 |
| `remark` | string | 否 | 空 | 报价单备注。 |
| `items` | array<object> | 是 | 无 | 报价商品列表，至少一项。 |
| `items[].goods_id` | integer | 是 | 无 | 商品 ID，必须来自商品搜索结果。 |
| `items[].quantity` | number | 否 | `1` | 购买数量，最小值 `0.01`。 |
| `items[].box_quantity` | number | 否 | `0` | 按箱计量的数量。 |
| `items[].carton_quantity` | number | 否 | `0` | 按整箱/纸箱计量的数量。 |
| `items[].discount_rate` | number | 否 | 无 | 当前商品的折扣率。 |
| `items[].manual_price` | boolean | 否 | `false` | 是否启用人工报价。 |
| `items[].quote_price` | number | 否 | 无 | 人工报价单价，仅在 `manual_price=true` 时使用。 |
| `items[].remark` | string | 否 | 空 | 当前商品备注。 |

以下字段不属于该接口，不能发送：`title`、`customerName`、顶层 `discount`、`items[].productId`。旧配置中的这些字段已经从百炼 MCP 删除或改名。

### 8.3 正确请求示例

```json
{
  "global_discount_rate": 100,
  "extra_amount": 0,
  "remark": "小程序直接创建",
  "items": [
    {
      "goods_id": 345,
      "quantity": 2,
      "discount_rate": 92,
      "remark": "单品九二折"
    },
    {
      "goods_id": 346,
      "quantity": 1,
      "manual_price": true,
      "quote_price": 128.5
    }
  ]
}
```

成功响应结构为：

```json
{
  "code": 1,
  "msg": "SUCCESS",
  "data": {
    "quote_id": 123
  }
}
```

本次没有执行 POST 测试，以免在业务系统生成垃圾报价单。上线前仍要由后端确认重复请求的幂等策略、用户权限、审计规则，以及小程序的二次确认流程。

## 九、百炼智能体 System Prompt

```text
你是“格宏 AI 助手”，是一名严谨的暖通空调和家用电器商品顾问。

1. 用户询问具体商品、型号或“有没有某商品”时，优先调用 search_products。
2. 用户询问技术参数时，先搜索获得 goods_id，再调用 get_product_detail；禁止猜测商品 ID。
3. 用户只描述分类但没有分类 ID 时，先调用 get_product_categories，再使用分类 ID 搜索。
4. 工具没有返回的数据必须说“系统暂无该参数”，严禁编造尺寸、冷量、能效、噪音、冷媒、管径或价格。
5. price 为 0 表示价格尚未维护或需要业务人员确认，不得说成免费。
6. 搜索结果较多时，先展示最相关的 3～5 个，再询问是否翻页或缩小范围。
7. 推荐商品时说明依据，明确区分接口中的确定信息与一般经验建议。
8. 最终报价、库存、安装条件和工程可行性以业务人员复核为准。
9. 未经用户明确确认，不创建报价单或执行其他写操作。

使用简洁中文。展示商品时优先包含商品名称、型号、分类、价格状态和商品 ID；参数详情按“参数名：参数值”列出。
```

## 十一、实施顺序

1. 立刻吊销已经出现在仓库或外发文档中的旧 API Key，并重新生成。
2. 准备稳定 HTTPS 域名，替换临时 cpolar 地址。
3. 为商品插件增加独立服务级鉴权、限流和脱敏日志。
4. 在百炼录入三个只读工具和一个报价创建工具；只读工具逐个在线测试，写工具先做结构审核。
5. 创建并发布“格宏 AI 助手”智能体，绑定插件。
6. 自有后端实现 `/api/ai/ask`，由后端调用百炼应用。
7. 把 `pages/ai/chat.vue` 的 Mock `setTimeout` 替换成 `askAi()`。
8. 测试多轮会话、空结果、超时、下架、价格为 0 和参数为空。
9. 在测试环境完成报价接口鉴权、幂等、权限和二次确认验收后，再允许生产智能体调用写工具。

## 十二、验收用例

| 测试问题 | 预期行为 |

| `帮我找 GMV 系列产品` | 调 `search_products`，keyword 为 `GMV`。 |

## 十三、安全清单

- 不在 Markdown、截图、前端代码或 Git 中保存真实 API Key。
- 不使用 `VITE_DASHSCOPE_API_KEY`，`VITE_*` 会进入客户端构建产物。
- 百炼 API Key 与商品插件访问 Token 必须分开。
- 插件接口做鉴权、限流、超时、日志脱敏和来源监控。
- 插件响应不要暴露成本价、内部折扣等敏感 `raw` 字段。
- 写操作校验用户、权限和幂等键，并保留用户确认步骤。
- Key 一旦出现在公开仓库、历史提交或外发文档中，应立即吊销；只删除当前文件不够。
